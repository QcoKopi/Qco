QCO Kopi Affiliate Platform

Dokumentasi lengkap sistem — sekaligus Handbook Administrator dan Blueprint Teknis untuk pengembangan lanjutan.

QCO Kopi Affiliate Platform adalah sistem e-commerce terintegrasi yang menggabungkan toko online, program affiliate berbasis komisi, chatbot AI di WhatsApp, dan otomatisasi penuh untuk pembayaran, pengiriman, komisi, dan bonus performa. Seluruh perjalanan — dari promosi, checkout, pembayaran, pengiriman, sampai pencairan komisi — berjalan otomatis tanpa campur tangan manual admin di setiap langkahnya.

Empat Pilar Utama

🛒

Toko Online

Checkout, ongkir otomatis, pembayaran inline, cek status pesanan mandiri.

🤝

Program Affiliate

Tracking referral, dashboard, leaderboard, komisi & bonus otomatis.

🤖

Chatbot AI WhatsApp

Memproses pesanan penuh dengan Claude AI, bukan sekadar auto-reply.

⚙️

Otomatisasi End-to-End

Pembayaran → pengiriman → komisi → bonus, semua saling terhubung.

Blueprint Teknis

B. Arsitektur Sistem

Sistem ini dibangun sepenuhnya di atas infrastruktur Google yang serverless (tanpa perlu sewa server sendiri), dipadukan dengan beberapa layanan pihak ketiga khusus untuk fungsi yang tidak disediakan Google secara native.

⚠ Kenapa perlu Cloudflare Worker?

Google Apps Script /exec URL selalu melakukan redirect (302) pada permintaan pertama. Xendit dan Biteship tidak mengikuti redirect ini saat mengirim webhook, sehingga permintaan gagal (ENOTFOUND). Cloudflare Worker berfungsi sebagai proxy yang mengikuti redirect secara internal, lalu mengembalikan status 200 ke pemanggil asli.

Catatan penting soal masing-masing integrasi

  • Biteship (mode test): status picked (paket diambil kurir) tidak pernah muncul otomatis selama masih pakai API key testing — ini keterbatasan resmi Biteship, bukan bug. Baru berjalan normal setelah pakai key production.
  • Xendit (mode test): transaksi tersimulasi, bukan uang sungguhan. Business verification perlu selesai dulu sebelum pakai key xnd_production_....
  • Meta/WhatsApp (belum verified): batas 250 percakapan business-initiated per 24 jam (Tier 0). Ini hanya berlaku untuk pesan yang DIMULAI bisnis (broadcast, notifikasi di luar 24 jam) — membalas pesan yang customer kirim duluan tidak terbatas ini.
  • Claude API (Anthropic): sistem prepaid murni, tidak ada kuota gratis harian seperti Meta. Kalau saldo di Console habis, API berhenti total sampai diisi ulang — disarankan aktifkan Auto-reload di platform.claude.com → Settings → Billing.

B.4 Model Keamanan

  • 🔐 Password: hash SHA-256 + salt — tidak pernah tersimpan polos, otomatis upgrade dari password lama saat login pertama kali
  • 🎫 Sesi login: berbasis token (sheet Sessions), divalidasi ULANG di server setiap request — tidak cukup cuma disembunyikan di tampilan browser
  • 🚦 Rate limiting: semua endpoint publik (submit lead, cek status pesanan, dll) dibatasi lajunya untuk cegah spam/brute-force
  • ✅ Verifikasi webhook: Xendit & Biteship diverifikasi pakai secret token khusus di query string — terpisah dari API key utama
  • 🔒 LockService: mencegah race condition pada proses kritis (konfirmasi pembayaran & komisi) — detail lengkap di B.5
  • 📋 Audit Trail: mencatat semua aksi sensitif admin, tidak bisa dihapus/diedit lewat aplikasi
  • 🔑 Kredensial: SELALU di Script Properties, tidak pernah hardcode di source code — lihat peringatan di E.4

B.5 Prinsip Desain & Lessons Learned

Beberapa keputusan desain yang lahir dari masalah nyata yang pernah terjadi selama pengembangan — penting dipahami sebelum mengembangkan lebih lanjut.

Satu jalur logika bisnis

Order dari WhatsApp diproses identik dengan order dari web — potong stok, hitung komisi, dst — semua lewat action Code.gs yang sama persis. WA-Bot.gs tidak menyimpan data sendiri dan tidak menduplikasi logika bisnis apa pun.

Race condition pada konfirmasi pembayaran

⚠ Kasus nyata: komisi dobel

Payment gateway seperti Xendit lazim mengirim webhook yang sama dua kali (untuk keandalan). Tanpa penguncian, dua permintaan bisa lolos pengecekan "sudah dibayar?" secara bersamaan sebelum salah satunya sempat menulis status — menghasilkan komisi tercatat dua kali. Solusinya: LockService.getScriptLock() membungkus markLeadPaidAndCalculateCommission(), memaksa permintaan kedua menunggu sampai yang pertama benar-benar selesai.

Idempotency di titik-titik kritis

Perhitungan bonus bulanan dan pembuatan order pengiriman Biteship dirancang aman dijalankan berkali-kali tanpa menghasilkan duplikasi — dicek lewat penanda unik (reference_id, atau deskripsi yang menyertakan [yyyy-mm]) sebelum benar-benar membuat entry baru.

Nilai yang bisa berubah, disimpan di Settings — bukan hardcode

Persentase komisi, target bonus bulanan, batas minimum payout, jadwal reminder — semua disimpan di sheet Settings, bisa diubah admin dari dashboard tanpa perlu edit kode maupun redeploy.

Placeholder dinamis untuk teks yang menyebut angka berubah

Alih-alih menulis ulang "5%" di banyak tempat (rawan lupa update sebagian), sistem pakai placeholder {{komisi}} yang disubstitusi otomatis di titik pemakaian — di teks Informasi affiliator, system prompt bot WhatsApp, dan Syarat & Ketentuan pendaftaran.

Satu nomor WhatsApp = satu webhook aktif

⚠ Batasan penting Meta

WhatsApp Business Platform cuma mengizinkan satu URL webhook aktif per nomor di satu waktu. Kalau lebih dari satu project Apps Script dikonfigurasi ke nomor yang sama, siapa pun yang terakhir didaftarkan di dashboard Meta yang benar-benar menerima pesan — yang lain berhenti menerima tanpa pesan error apa pun. Lihat E.4 untuk detail lengkap.

C. Alur (Flow) Sistem

Tujuh alur inti yang menggerakkan sistem ini, dari sisi pembeli, affiliator, maupun admin.

C.1 Alur Checkout — Landing Page

1
Pilih produk, isi keranjang
2
Kode pos & ongkir otomatis
3
Submit → Lead + Invoice Xendit dibuat
4
Modal bayar (iframe) di halaman sama
5
Polling status tiap 4 detik
6
Kode pesanan + ajakan jadi affiliator

Ongkir dihitung otomatis lewat Biteship Rates API begitu pembeli memilih kode pos dari hasil pencarian. Pembayaran berjalan inline (iframe) tanpa pindah tab — begitu Xendit mengonfirmasi lunas (via webhook, dideteksi lewat polling), modal otomatis tertutup dan kode pesanan ditampilkan untuk disimpan.

C.2 Alur Pemesanan via WhatsApp Bot

1
Chat masuk (link referral tertangkap otomatis)
2
Bot pakai tool get_products (tidak mengarang)
3
Kumpulkan pesanan via add_to_cart
4
Validasi alamat via check_postal_code
5
Ringkasan + konfirmasi eksplisit
6
submit_order → Lead+Order via Code.gs

Bot menggunakan agent loop dengan tool-calling (maksimal 6 giliran per balasan) — bukan keyword matching kaku. Setiap tool memvalidasi data ke server secara real-time (harga, stok) sehingga bot tidak pernah "mengarang" informasi. System prompt & persona bisa diedit admin dari wa-admin.html tanpa ubah kode.

C.3 Alur Konfirmasi Pembayaran → Komisi → Fulfillment

1
Webhook Xendit "Paid" masuk
2
LockService cegah proses ganda
3
Lead → Valid, Order → Diproses
4
Komisi dihitung & dicatat
5
1 paket Biteship untuk seluruh Lead
6
Webhook "picked" → status Dikirim

Satu pembeli yang beli 3 produk sekaligus menghasilkan satu paket, satu resi — bukan tiga pengiriman terpisah. Admin bisa juga menandai manual "Diterima" karena tidak semua mode kurir mengirim update status final secara otomatis.

C.4 Alur Cek Status Pesanan (Mandiri oleh Pembeli)

1
Klik "Cek Status Pesanan"
2
Isi Kode Pesanan + No. HP
3
Verifikasi 8 digit terakhir HP
4
Tampil status, resi, kurir
5
Ajakan jadi affiliator (jika belum)

Verifikasi 2 faktor (kode + nomor HP) sengaja diterapkan — kode pesanan saja tidak cukup karena formatnya lead_+timestamp yang bisa ditebak. Momentum ajakan jadi affiliator ditempatkan tepat setelah pembeli merasakan kemudahan self-service ini.

C.5 Alur Pencairan Komisi Mingguan

1
Trigger jam-an cek jadwal (default Jumat 9 pagi)
2
Notifikasi WA ke admin kalau ada yang eligible
3
Admin Refresh daftar & verifikasi rekening
4
Klik Kirim → Xendit Disbursement API
5
Komisi ditandai lunas, WA notifikasi

Kode bank & nomor rekening ditebak otomatis dari data pendaftaran, tapi wajib diverifikasi manual oleh admin sebelum klik Kirim — ini uang sungguhan dan tidak bisa dibatalkan setelah terkirim.

C.6 Alur Bonus Bulanan (Target & Peringkat Penjualan)

1
Tanggal terjadwal (default tgl 1), hitung bulan lalu
2
Affiliator ≥ target → bonus % dari total
3
3 penjualan terbesar → bonus tambahan
4
Masuk sheet Commissions (entry baru)
5
WA "Selamat!" segera, transfer ikut jadwal payout

Reset bersih tiap bulan — tidak ada akumulasi dari bulan sebelumnya (dikonfirmasi eksplisit saat perancangan). Kedua jenis bonus masuk sebagai entry baru di sheet Commissions dengan type berbeda ("Bonus Target Bulanan" / "Bonus Peringkat Penjualan"), sehingga otomatis ikut alur payout & notifikasi yang sudah ada — tidak perlu sistem pembayaran terpisah.

C.7 Alur Eskalasi ke Admin/Sales

1
Bot deteksi kebutuhan eskalasi (atau 3x tanpa progres)
2
Sesi ditandai humanTakeover, bot berhenti balas
3
Dicatat ke sheet Escalations + WA admin/sales
4
Admin balas manual dari dashboard
5
Kembali ke bot (manual/diam 10 mnt/30 mnt maks)

Selain eskalasi eksplisit (komplain, sengketa), ada juga jaring pengaman mekanis: kalau 3 balasan berturut-turut tidak menghasilkan progres nyata, bot otomatis diinstruksikan menawarkan sambungan ke admin — tidak hanya mengandalkan Claude "sadar sendiri".

D. Panduan Operasional

Langkah demi langkah menjalankan sistem sehari-hari — dari setup awal (sekali jalan) sampai operasional rutin per menu.

D.1 Setup Awal (Sekali Jalan)

📌 Kapan bagian ini dipakai

Hanya perlu dilakukan sekali di awal, atau setiap kali ada perubahan besar (ganti API key, redeploy dengan URL baru). Setelah selesai, cukup ikuti D.2 untuk operasional harian.

a. Deploy Code.gs & WA-Bot.gs

  1. Buka project Apps Script, klik Deploy → Manage Deployments
  2. Klik ikon pensil pada deployment aktif → pilih "New version" → Deploy
  3. Ulangi persis sama untuk project WA-Bot.gs yang terpisah

b. Aktifkan Keamanan & Password Admin

  1. Di editor Code.gs, jalankan fungsi setupSecurity() sekali dari dropdown fungsi
  2. Buka ⚙️ Project Settings → Script Properties, tambahkan TEMP_NEW_ADMIN_PASSWORD dengan password pilihan (min. 6 karakter)
  3. Kembali ke Editor, jalankan fungsi updateAdminPassword()
  4. Password langsung aktif — tidak perlu redeploy

c. Sambungkan WA-Bot ke Sistem Utama

  1. Di WA-Bot.gs, jalankan setupWABotSecurity()
  2. Jalankan updateAppSecretDanMainUrl()
  3. Di Code.gs, jalankan updateWABotSecretDiSistemUtama()

d. Konfigurasi API Pihak Ketiga

Isi manual di Script Properties: XENDIT_SECRET_KEY, BITESHIP_API_KEY, ANTHROPIC_API_KEY, alamat pengirim (SHIPPING_ORIGIN_*).

e. Pasang Proxy Cloudflare Worker & Daftarkan Webhook

  1. Buat 2 Worker terpisah (Xendit & Biteship) di workers.cloudflare.com
  2. Jalankan checkXenditSetup() / checkBiteshipWebhookSetup() untuk dapat URL webhook lengkap
  3. Daftarkan URL Worker (bukan URL Apps Script langsung) di dashboard masing-masing layanan

f. Aktifkan Trigger Otomatis

  • setupReminderTrigger() di WA-Bot.gs — cek eskalasi tiap 5 menit
  • setupPayoutReminderTrigger() di Code.gs — reminder payout tiap jam
  • setupMonthlyBonusTrigger() di Code.gs — hitung bonus bulanan tiap hari jam 8 pagi

D.3 Troubleshooting Umum

Ongkir tidak muncul saat checkout

Pastikan pembeli benar-benar memilih kode pos dari dropdown hasil pencarian (bukan cuma mengetik). Cek juga apakah berat produk sudah diisi benar di Manage Products.

Pembayaran sudah masuk tapi status Lead belum berubah

Jalankan testXenditWebhookSimulation() dari editor untuk memastikan logika sistem benar. Kalau simulasi berhasil tapi transaksi sungguhan tetap tidak berubah, cek status webhook "Invoices paid" di dashboard Xendit — pastikan aktif, bukan cuma tersimpan.

Status kurir tidak pernah berubah jadi "Dikirim"

Kalau masih pakai API key test/sandbox Biteship, status picked memang tidak akan pernah muncul otomatis — keterbatasan resmi Biteship, bukan bug. Gunakan tombol "Tandai Diterima" sebagai alternatif manual, atau tunggu sampai pakai key production.

Komisi affiliator tercatat dobel

Ini masalah race condition yang sudah diperbaiki lewat LockService (lihat B.5). Kalau masih terjadi di versi terbaru, pastikan Code.gs sudah di-redeploy dengan versi yang benar-benar terbaru — cek lewat checkDeploymentVersions().

Data (Leads/Orders/Komisi/Affiliator) tiba-tiba kosong semua, kecuali Produk

Ini hampir selalu berarti sesi login sudah kedaluwarsa (berlaku 24 jam). Produk tetap tampil karena itu data publik yang tidak butuh sesi. Solusinya: logout, lalu login ulang.

Data kadang muncul, kadang tidak, walau sudah login

Kemungkinan Apps Script sedang lambat/sibuk saat beberapa data ditarik bersamaan. Sistem sudah punya retry otomatis (3x percobaan) — kalau tetap gagal setelah itu, akan muncul pesan jelas "Gagal memuat data: [nama data]. Coba klik Refresh lagi." Ini pertanda genuinely perlu di-refresh manual, bukan bug diam-diam.

Lupa password admin

Ulangi langkah D.1.b — fungsi updateAdminPassword() selalu bisa dipakai kapan saja tanpa perlu tahu password lama.

E.3 Cara Menambah Fitur Baru

  1. Backend dulu: tambahkan fungsi handleXxx(spreadsheet, params) di Code.gs, daftarkan di ADMIN_ACTIONS/AUTH_ACTIONS kalau perlu proteksi, tambahkan case di executeAction()
  2. Nilai yang bisa berubah → Settings: jangan hardcode angka/teks yang mungkin berubah — simpan lewat setSettingValue()/getSettingValue(), ikuti pola getBonusSettings() sebagai contoh
  3. Idempotency: kalau fitur baru bisa terpanggil berkali-kali (webhook, trigger), pastikan ada penanda unik sebelum membuat entry baru — lihat pola di calculateMonthlyBonuses()
  4. Race condition: kalau fitur menyentuh uang/status kritis yang bisa terpanggil bersamaan, bungkus dengan LockService.getScriptLock()
  5. Frontend: tambahkan UI di index.html/landing.html, panggil lewat callGASPost()/fetchFromGAS() (yang di index.html sudah ada retry otomatis — pakai fetchFromGASWithRetry() untuk konsistensi)
  6. Validasi selalu di server: jangan percaya validasi frontend saja — cek ulang di backend (lihat pola isValidLength(), isValidPositiveNumber(), dst)

E.4 Peringatan Arsitektur

⚠ WA-Bot.gs WAJIB project terpisah

Kalau digabung dengan Code.gs di project yang sama, fungsi doGet/doPost keduanya akan tabrakan — salah satu diam-diam berhenti berfungsi. Ini pernah terjadi sebelumnya.

⚠ Satu nomor WhatsApp = satu webhook aktif

Kalau ada lebih dari satu project Apps Script (mis. untuk bisnis/unit berbeda) dikonfigurasi ke nomor WA yang sama, siapa pun yang terakhir didaftarkan sebagai webhook di dashboard Meta yang benar-benar menerima pesan — yang lain berhenti menerima tanpa error apa pun. Kalau perlu satu nomor melayani beberapa "kepribadian" bot (seperti integrasi CRM terpisah), pisahkan logikanya lewat deteksi di dalam kode yang sama (satu deployment, banyak jalur logika) — bukan banyak deployment berebut satu nomor.

⚠ Jangan pernah hardcode kredensial di source code

ANTHROPIC_API_KEY, WA_ACCESS_TOKEN, WA_APP_SECRET, dan sejenisnya selalu lewat Script Properties, tidak pernah ditulis langsung di kode — terutama karena kode bisa saja suatu saat ditempel/dibagikan ke tempat lain (termasuk ke asisten AI untuk debugging), dan kredensial yang sempat ter-expose harus dianggap bocor dan digenerate ulang.

💡 Kalau ada integrasi pihak ketiga LAIN (seperti CRM/QSystem)

Pola yang dipakai: project terpisah, otentikasi lewat secret bersama (WA_BOT_SECRET), dan jalur logika yang sengaja dipisah total di dalam WA-Bot.gs (deteksi nomor di awal processIncomingMessage(), lalu routing ke agent loop yang sesuai). Prinsipnya: kemampuan tiap agent dibatasi SEKETAT mungkin sesuai tugasnya — agent CRM misalnya cuma boleh satu tool (escalate_to_crm_staff), tidak diberi akses order/checkout sama sekali walau secara teknis bisa.

F. Tanya Jawab

Kumpulan pertanyaan nyata yang paling sering muncul selama pengembangan sistem ini.

Apakah orang lain bisa masuk ke dashboard tanpa password?

Tidak. Kalau terasa "masuk tanpa password", itu karena sesi login tersimpan di browser yang sama yang pernah dipakai login sebelumnya (fitur "tetap login", supaya tidak perlu ketik ulang tiap buka halaman). Token tetap divalidasi ke server setiap ada aksi. Cara pastikan: coba buka di jendela Incognito/browser lain yang belum pernah login — kalau di situ tetap diminta password, sistem aman.

Apa beda status Lead "Valid" dan "Converted"?

Keduanya dihitung sama sebagai "transaksi berhasil" untuk komisi & bonus — bedanya cuma jalur. Valid = otomatis oleh sistem begitu pembayaran Xendit terkonfirmasi. Converted = ditandai manual oleh admin, untuk penjualan yang closing-nya di luar jalur otomatis (mis. transfer manual, chat WhatsApp).

Apakah bot WhatsApp bisa broadcast pesan massal?

Belum dibangun. Yang ada sekarang cuma kirim satu-satu ke nomor tertentu. Kalau mau dibangun, perlu diperhatikan: WhatsApp mewajibkan Message Template yang disetujui Meta untuk pesan yang dikirim di luar jendela 24 jam sejak customer chat terakhir, dan ada batas ±2 pesan marketing/hari/user (gabungan semua bisnis).

Berapa kuota pesan WhatsApp kalau bisnis belum verified?

250 percakapan business-initiated per 24 jam (Tier 0). Ini hanya berlaku untuk pesan yang dimulai bisnis (broadcast, notifikasi di luar 24 jam) — membalas pesan yang customer kirim duluan tidak terbatas ini. Setelah verified, langsung naik ke 1.000, lalu bisa lanjut lebih tinggi tergantung kualitas & pemakaian.

Bagaimana cara kerja billing Claude API — ada kuota gratis harian?

Tidak ada kuota gratis harian seperti Meta. Claude API (lewat platform.claude.com, bukan Claude.ai) murni prepaid — kalau saldo Console habis, API berhenti total sampai diisi ulang manual. Satu-satunya "gratis" cuma kredit awal sekali saat pertama daftar. Disarankan aktifkan Auto-reload di Settings → Billing supaya bot tidak tiba-tiba bisu.

Kenapa modal pembayaran Xendit sempat membuka tab baru sendiri?

Penyebabnya success_redirect_url yang diarahkan ke URL Apps Script sendiri — URL itu tidak bisa dimuat di dalam iframe (dibatasi kebijakan keamanan Google), jadi browser "kabur" membuka tab baru sebagai jalan keluarnya. Sudah diperbaiki dengan menghapus field ini sepenuhnya — status pembayaran sudah dideteksi lewat polling, bukan lewat redirect ini.

Apa yang membedakan agent CRM dan agent Affiliate di WA-Bot.gs?

Keduanya berbagi nomor WA & mekanisme sesi, tapi logika bisnisnya sengaja dipisah total. CRM melayani client wholesale/B2B existing (deteksi di awal processIncomingMessage()), cuma punya 1 tool (escalate_to_crm_staff) dan tidak bisa checkout/order sama sekali — kalau mau order, diarahkan ke sales manual. Affiliate melayani pembeli retail baru, punya 8 tool lengkap dari lihat produk sampai submit pesanan. Pembatasan tool CRM itu disengaja — bukan kekurangan fitur, tapi pagar supaya bot tidak pernah salah memproses transaksi wholesale sendiri.

Amankah satu nomor WhatsApp dipakai lebih dari satu project/bisnis?

Berisiko kalau masing-masing dijalankan sebagai deployment Apps Script yang berbeda dan berebut jadi webhook nomor yang sama — WhatsApp cuma izinkan satu webhook aktif per nomor, jadi salah satu akan berhenti menerima pesan tanpa error apa pun. Solusi yang aman: satu deployment saja yang jadi webhook, dengan logika di DALAM kode yang mendeteksi & memilah jenis customer/bisnis (seperti pola CRM vs Affiliate di atas).

Bagaimana cara ganti password admin?

Isi Script Property TEMP_NEW_ADMIN_PASSWORD dengan password baru (nama property-nya tetap, isinya bebas), lalu jalankan fungsi updateAdminPassword() dari editor. Langsung aktif tanpa redeploy, dan property sementara itu otomatis terhapus sendiri setelah dipakai.

Kenapa komisi kadang tidak muncul walau sudah login?

Kemungkinan besar Apps Script sedang lambat/sibuk memproses beberapa permintaan data sekaligus. Sistem sudah dilengkapi retry otomatis (3x percobaan) untuk kegagalan sesaat seperti ini — kalau tetap gagal setelahnya, akan muncul pesan jelas yang meminta refresh manual, bukan diam-diam kosong tanpa keterangan.
